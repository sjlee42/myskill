# tool-finder 테스트 결과 (2026-11-23)

skill-creator의 평가 절차로 3차례 비교했다. 테스트 사례는 [`skills/tool-finder/evals/`](../skills/tool-finder/evals/)에 있는 3개다.

| 사례 | 요청 | 확인하려던 것 |
|---|---|---|
| `ktx-booking-removed` | "KTX 예매를 하는 스킬을 찾고 있어. 최근에 잘 만든 것도 포함해서" | 디렉터리에는 남아 있지만 저장소에서 지워진 skill, 기반 라이브러리가 막힌 도구를 걸러 내는가 |
| `admin-mail-folder-combo` | "학생 질의 메일을 내 디렉토리와 연결해 맞는 위치를 알려주는 플러그인이나 스킬" | 한 도구로 안 되는 요구를 기능으로 쪼개 조합하는가, 개인정보와 권한을 정확히 짚는가 |
| `cover-letter-vague` | "자소서 준비해야 되는데 도움이 될 만한 거 좀 찾아줘" | 막연한 요청에서 이미 설치된 도구와 한국어 전용 도구를 찾는가 |

채점 항목은 사례마다 6개다. 이 중 "정확히 맞는 게 없다"고 결론 낼 때 찾아본 범위와 가장 가까운 후보 3개, 각각 빠진 기능을 적었는지 보는 항목은 세 사례에 공통이다. 그 밖에 다른 실행이 찾은 도구로 "없다"는 결론이 뒤집히는지(반례)를 따로 봤다.

## 방법

- 실행과 채점을 서로 다른 세션에서 했다. 실행 세션은 채점 기준과 이전 결과를 볼 수 없게 막았다.
- 2·3차 채점은 블라인드로 했다. 채점 세션은 보고서를 A/B/C로만 받았고(사례마다 순서를 바꿈), 경로처럼 버전이 드러나는 흔적은 지웠다.
- 채점 세션은 "없다"는 결론마다 직접 6~10번 검색해 반례를 찾았다. 각 보고서 1순위가 실제로 있고 지금 동작할 것 같은지는 GitHub 메타데이터, 이슈, PyPI·npm 배포 상태로 확인했다. 아무것도 설치하거나 실행하지 않았다.
- 버전마다 1회씩만 실행했다. 1항목 차이는 우연일 수 있다.

### 1차에서 확인한 것
- skill 없이 찾으면 "없다"고 결론 내도 어디를 몇 건 찾아봤는지 남기지 않았다. "없다"의 증명 항목은 skill 쪽만 3/3 통과했다.
- skill 쪽만 찾은 도구: HWP 문서를 검색하는 `lupa-mcp`, 읽기 전용 메일 MCP, Claude에서 쓰는 한국어 맞춤법 skill 등.
- 약점: 지워진 skill의 직전 버전을 "고정해서 쓰면 된다"고 추천했는데, 그 기반 라이브러리는 이미 로그인이 막혀 있었다(`carpedm20/korail2` #60). 파일이 있는지만 보고 지금 동작하는지는 보지 않았기 때문이다.

### 2차: 기능을 붙였더니
- 존재·동작 확인 스크립트(`liveness.py`)를 넣었다. 덕분에 KTX 사례에서 막힌 도구를 걸러 냈다.
- 그런데 다른 곳에서 새 실수가 나왔다.
  - 검색어를 영어로만 만들어서 한국 자소서 전용 skill(`thesun4sky/jobstack` ★225)을 놓치고 "없다"고 했다.
  - 공식 메일 커넥터를 추천하면서 "학생 개인정보가 외부 서버를 거치지 않는다"고 잘못 적었다. 메일 본문은 Anthropic으로 간다.
- SKILL.md는 243줄로 늘었다.

### 3차: 줄였더니
- SKILL.md를 94줄로 줄였다. 효과가 확인된 것만 남겼다: 기능 분해, 이미 있는 것과 공식 기능을 먼저 확인, 여러 디렉터리를 한 번에 검색, 설치 없이 존재·동작 확인, "없다"의 근거 남기기.
- 뺀 것: README 검증용 서브에이전트(WebFetch만으로도 결과가 같았다), 모델 배치 표, 긴 규칙 목록.
- 2차의 실수는 기능을 더하지 않고 문장 두 개로 고쳤다.
  - "한국 맥락이면 한국어 검색어도 섞는다"
  - 데이터 칸에 "로컬 / Claude(Anthropic) / 제3자 서버"를 구분해 적는다
- 결과:
  - 자소서: 한국어 자소서 전용 도구 3개를 v3만 찾았다.
  - 메일: 공식 커넥터와 HWP를 읽는 `kordoc`을 함께 1순위로 올렸고, 개인정보 설명도 정확했다.
  - KTX: 원본 skill 삭제, 법적 검토(위험 HIGH), 라이브러리 차단, 의존 패키지 삭제를 모두 근거로 연결했다.

## 남은 약점

- 실행마다 찾는 범위가 조금씩 다르다. 3차 KTX에서 v3는 최근 도구 3개를 놓쳤고, 다른 실행이 놓친 도구 2개를 찾았다.
- 한 후보를 "유일한 후보"라고 쓴 문장은 채점 세션이 찾은 반례로 과장이었다.
- v1보다 시간이 22~81% 더 든다. 존재·동작 확인과 공식 기능 확인에 드는 비용이다.
