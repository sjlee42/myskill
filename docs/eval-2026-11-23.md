# write-with-me 개선 테스트 (2026-11-23)

이전 버전(커밋 30e1b6e)과 개선 버전을 같은 가상 사용자로 비교했다. 인터뷰형 skill이라 실행자가 사용자를 함께 연기했고, 사용자는 미리 정한 사실 파일에 있는 것만 답했다(없는 건 "기억 안 나요"). 웹 조사와 6단계 블라인드 심사는 비용 때문에 뺐다. 채점과 비교는 버전을 가린 A/B로 별도 에이전트가 했다.

## 관찰

- **새 버전이 나은 점**: "제 손이 많이 간 문장"으로 초안을 보여 주자 사용자가 자기 말이 아닌 표현을 실제로 짚어 냈다. 요지를 사용자에게 먼저 물었고, 답을 평가하지 않았고, 면접 대비 확인으로 불확실한 수치를 사용자가 직접 뺐다. AI 금지 공고에서는 첨삭 금지라는 애매한 지점까지 알리고 피드백을 질문으로만 했다.
- **이전 버전도 통과한 것**: AI 금지 규정 감지와 대필 거부는 규칙이 없어도 모델이 스스로 했다. 새 규칙은 공고가 덜 분명할 때를 위한 안전장치다.
- **새 버전의 감점**: 질문법 예시가 질문 두 개를 한 문장에 묶어 두어, 모델이 그대로 따라 했다. → 예시의 후속 질문을 `→`로 분리하고 "물음표 하나" 규칙을 명시했다.
- **두 버전 공통 누락**: "왜 여기인가"와 판단 지점(반대를 어떻게 넘었나, 왜 그 방법인가)을 묻지 않고 인터뷰가 끝났다. → `questioning.md` 8절에 멈추기 전 이 둘을 먼저 확인하는 규칙을 넣었다.

위 두 수정은 이 테스트 뒤에 반영했고, 아직 다시 돌려 보지 않았다.

## 2차 (같은 날, 개선 2회차)

반영한 것: 숫자 검사 스크립트 `check_facts.py`(근거에 없는 숫자 ✗, 사용자가 불확실하게 말한 숫자 △, 공고 속 숫자는 `--notice`), `count.py --count-newlines`, 본인/팀·수치 확실성 태그, 문항별 근거 등급(충분/보통/얇음), AI 사용 규정 5단계, 제출 전 3분류, skill-creator 기준 검토 47건(description 정리, 끊긴 참조·중복 정리, 근거 인용 축소).

1차 새 버전(9f93a1e)과 비교했다. 가상 사용자에게 본인 몫, 회사 선택 이유, 판단 이유를 답할 사실을 더 줬다(두 버전 동일).

| | 2회차 | 1회차 |
|---|---|---|
| 기준 통과율 | 100% | 100% |
| 블라인드 비교 (사례1) | 16 | 16 (동점, 근소하게 1회차 선택) |
| 블라인드 비교 (사례2) | 18 | 17 |
| 시간 | 490초 | 323초 |
| 토큰 | 10.8만 | 9.6만 |

- 기준은 둘 다 모두 통과했다. 1차에서 고친 '왜 여기'·판단 지점 규칙이 1회차 버전에 이미 들어 있어서 변별이 안 됐다. 다음 테스트는 더 어려운 기준이 필요하다.
- 2회차가 나은 점: 숫자가 기록인지 기억인지 확인하고 불확실한 수치를 낮추거나 뺐다. 판단 이유와 설득 방법을 따로 물었다. 숫자 검사가 사용자 초안의 "두 배"를 실제로 잡았다.
- 2회차의 약점 → 바로 고침: (1) 가장 강한 재료를 선택 문항용으로 아껴 필수 문항이 추상적이 됐다 → 강한 재료는 필수 문항에 먼저 쓰는 규칙. (2) AI 금지 공고에서 외부 AI 심사위원을 제안했다 → `금지`·`제한`이면 묻지도 쓰지도 않는 규칙. 이 두 수정 후에는 다시 돌리지 않았다.
- 시간이 약 50% 늘었다. 숫자 확인 질문, 근거 등급 판단, 스크립트 실행 몫이다.
